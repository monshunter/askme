# EVO-002：delivery trace 应按 Journal Plan 字段确认归属

Session Review 结果：`OBSERVATION`

状态：`observation`

来源：[BUG-004](../../bugs/BUG-004.md)、[PLAN-008](../../plans/PLAN-008.md)

## 观察

`validate_delivery_trace.py` 曾以“Journal 全文包含 Plan ID”判定 delivery 归属。`PLAN-008` Journal 仅在 Evidence 中提及 `PLAN-001`，就让 `PLAN-001` 历史 audit 错误认为 delivery Journal 已存在。

Askme 已将匹配收紧为只解析 `Plan：` 字段，并通过 Red/Green 回归和历史/当前 Plan 对照验证。

## 影响与建议

- 该问题属于确定性 validator 的 owner 身份解析缺陷，可能让 audit 或 strict close 误用其他 Plan 的 Journal。
- 建议将 Askme 的最小修复与回归测试同步到 AutoGo 源实现，再通过正常安装生命周期投影。
- 当前只出现一次，且现有结构字段已足够修复；不新增规则、状态、Skill 或外部依赖。

## 验证与升级条件

- Askme 回归测试与 `PLAN-001` audit / `PLAN-008` strict 对照成立后，本 Observation 即可作为上游同步输入。
- 只有再次出现类似“全文搜索代替结构 owner”的误判，或 AutoGo 投影无法稳定保留修复时，才升级为 Candidate/Proposal。

## 复杂度与回滚

当前 Delta 只是一个字段精确匹配和一个回归用例。回滚可还原 validator、测试和 manifest 哈希；不影响产品代码、数据或运行环境。
