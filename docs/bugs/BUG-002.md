# BUG-002：公共问题检索漏召回并可能复用无关上一轮证据

状态：`verified/closed`

关联 Plan：[PLAN-003](../plans/PLAN-003.md)

## 现象与影响

公共页面从真实 Knowledge Item 生成的问题 `What did you build in Inkstone Career Agent?` 最初返回资料不足；修复漏召回后，完整 smoke 又发现新的独立无证据问题可能借用 Orion 项目的上一轮证据并被 AI 作答。前者让可见推荐失效，后者会破坏“每个事实只由当前问题相关授权证据支撑”的核心边界。

## 根因与促成因素

第一处根因是把完整自然语言问句交给 `websearch_to_tsquery`，空格形成 AND 语义，标题和证据虽包含关键实体却无法同时满足所有问句词。第二处根因是公共多轮服务在当前检索为 0 时无条件复用最近一个允许问题的证据，没有区分上下文追问与新的独立问题。静态通用推荐还可能在无知识数据时制造不可回答入口。

## 修复

- 检索去除英语问句样板词，对最多 24 个唯一 Unicode token 使用 OR 语义，并保留原问题的 ILIKE 精确兜底。
- 推荐问题完全由当前 Knowledge Item 生成；无知识数据时返回空数组，不注入静态演示问题。
- 只有包含明确英文或中文上下文指代的追问允许复用上一轮证据；独立问题检索为 0 时直接进入无证据结果。

## 验证与预防

- retrieval input 与 public question policy 定向测试覆盖目标实体、追问指代和独立问题；当前全量为 31 files / 108 tests PASS。
- Chrome 点击真实推荐问题后得到 42% DeepSeek 回答和 1 条真实 Citation。
- 完整 Public Chat smoke 同时证明上下文追问仍有 2 次真实 DeepSeek/Citation，独立 submarine patent 问题返回 `INSUFFICIENT_EVIDENCE`，注入、越界、限流与权限脱敏继续 PASS。
- 最小预防措施是把“UI 生成的问题必须真实可检索”和“证据复用必须由显式上下文指代触发”作为同一条端到端回归链路。
