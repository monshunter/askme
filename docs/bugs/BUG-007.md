# BUG-007：Repository Analysis 因 Runner 生命周期缺失与预算策略漂移永久 pending 或耗尽轮次

状态：`verified/closed`

关联 Plan：[PLAN-027](../plans/PLAN-027.md)

关联 Operation：[OP-011](../operations/OP-011.md)

## 现象与影响

本地 Compose 全部业务容器健康时，两个已成功同步的公开 Repository Analysis 长期停留在 `pending`，没有 Dossier 或可审核 Wiki。人工启动 host-native Runner 后，重复 Ferry 任务串行占用唯一仓库槽；清理重复任务后，Ferry 又先后在 50 轮和扩大后的 100 轮预算上失败为 `CODE_AGENT_GUEST_PROMPT_REQUEST_BUDGETROUNDS_FAILED`。

问题使 Candidate 无法审核或批准这两个公开仓库的 Wiki，Repository 也无法进入后续 RAG 索引。只看 Compose health 会误判系统可用；只增加预算会让大仓库探索更久，但仍可能在写出前耗尽轮次。

## 根因与促成因素

- Code Agent 使用 macOS host-native BoxLite，不能由 Compose worker 代替；但 `scripts/docker-up.sh -d` 只启动 Compose，没有拥有 Runner 生命周期。`/api/health/ready` 已正确暴露 Runner stale，启动文档却没有把完整环境命令写清楚。
- 初次尝试的 launchd current-session job 因仓库位于 macOS `Documents` 下而被 TCC 拒绝访问。系统服务不具备当前终端的目录权限，也不满足用户要求的 Linux/macOS 同一入口。
- 调度器默认全局并发 2，并保留 1 个对话槽，因此只能串行执行 1 个 Repository Analysis；Runner 缺失期间的多次“重新分析”形成重复 generation，恢复后依次消耗时间。
- Repository 工具预算只按调用次数锁定源码工具。默认从 80 次提高到 300 次后，软/硬锁从 48/60 推迟到 268/280；100 轮的模型边界先被耗尽。Repository Skill 仍写着旧的 44 轮、80 次调用、48/60 次源码调用，配置、运行策略和提示合同不一致。

## 修复

- 将 `scripts/docker-up.sh -d` 定义为完整本地启动入口：Compose 成功后用跨平台 `nohup` 启动 `scripts/agent-runner.sh`。项目 PID/lock 提供同 checkout 去重与 stale 恢复；README 记录完整启动、日志、readiness、人工恢复和显式 Compose-only 命令。
- 新增 host Runner 环境解析入口，统一 process env、项目 `.env`、`~/.env` 与本地默认值，安全处理 PostgreSQL URL、Artifact/BoxLite 路径、OCI digest 和一次性 Token。
- 默认全局并发改为 3，使两个 Repository Analysis 可并行并保留一个对话槽；默认 Repository Analysis 硬边界改为 30 分钟、100 轮、300 次调用。
- 增加轮次与调用双重收敛：默认 80 轮达到覆盖即锁源码工具，90 轮无条件锁；调用侧仍使用 268/280 软硬锁。Skill、纯预算函数、guest runtime 与 OCI 镜像保持同一合同。
- 按用户授权删除 Ferry 重复失败任务，只保留最终成功 run；Goat 唯一成功 run 保持不变，不自动批准 Wiki 或删除业务数据。

## 验证与预防

- 新 Runner digest 下，Ferry 在 71 轮、150 次调用内完成，检查 66 个文件，生成 6 页 Wiki 与 86 条 Citation；Goat 在 24 轮、57 次调用内完成，生成 4 页与 33 条 Citation。两个任务均为 `completed / review_pending` 且 cleanup 已完成。
- `/api/health/ready` 的 database、migration、worker、runner、artifact、BoxLite、provenance 全部为 `ready`；没有残留 microVM 进程。Repository/Revision 数量前后保持 `5 / 5`。
- Vitest `107 files / 433 tests`、ESLint、Typecheck、Build `31 / 31`、Surface Matrix 与 Diff 检查通过。预算测试固定默认/legacy/纠错轮次门槛和软硬锁组合；入口测试使用隔离 state root，不再污染真实 Runner 日志。
- 最小预防措施是：本地完整启动必须以 Code Agent readiness 而不是 Compose 容器数判断；当任一预算默认值变化时，Skill 文本、软硬收敛策略、profile fingerprint、OCI image 和新任务 `budget_snapshot` 必须一起对账；扩大工具预算时必须保留独立轮次写出预算，不能假设工具调用数与模型轮次同步增长。
