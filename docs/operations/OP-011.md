## 生命周期、配置与部署

- `scripts/docker-up.sh -d` 现在在 Compose 成功后调用 `nohup scripts/agent-runner.sh >> data/agent-runner/nohup.log 2>&1 &`；`ASKME_SKIP_AGENT_RUNNER=1` 是显式 Compose-only 入口。`scripts/agent-runner.sh` 使用项目内 PID/lock 去重并回收 stale lock，不依赖 launchd、systemd 或其他系统服务。
- `scripts/start-agent-runner.ts` 统一 process env、项目 `.env`、`~/.env` 与本地默认值，安全构造 host PostgreSQL URL、解析 OCI digest，并在进入 Runner 前删除一次性 GitHub Token。README 已记录完整启动、日志、readiness、人工恢复、Compose-only 和环境覆盖命令。
- 默认 Code Agent 全局并发为 3；既有调度器保留 1 个对话槽，因此默认最多并行执行 2 个 Repository Analysis。Repository Analysis 默认预算为 30 分钟、100 个模型轮次和 300 次工具调用。
- 使用 `scripts/build-code-agent-image.sh` 重建 host-native OCI layout，最终 digest 为 `sha256:5c02aa86d90480ba9b4da7bd210f99c159bab66a5cbaf4e3b969d97d2faf80e9`。随后使用 `scripts/docker-up.sh -d` 保留 PostgreSQL、uploads 与 Repository Artifact volume 完成重部署；migrate exit 0，Web healthy，worker running。
- Codex 自动化命令宿主会在启动命令退出后回收 detached descendant，因此 `nohup` launcher 在本次工具会话中不能作为持续存活 Evidence；该限制没有被写成应用故障。最终运行验收使用同一个 `scripts/agent-runner.sh` 持久前台会话，Runner heartbeat 与 readiness 持续有效。普通 macOS/Linux 终端仍使用 README 中的 `nohup` 命令，进程掉线后按用户要求人工重启。

## Ferry 收敛故障与修复

- 恢复 Runner 后，Ferry 旧 `50 rounds / 80 calls` 任务和新 `100 / 300` 任务都以 `CODE_AGENT_GUEST_PROMPT_REQUEST_BUDGETROUNDS_FAILED` 终止；租约持续刷新、失败反馈与 microVM cleanup 时间均正常，证明不是 Runner 或 BoxLite 卡死。
- 根因是 `budget-policy.mjs` 只按工具调用预留 Wiki 写出预算。总调用上限升至 300 后，源码工具软/硬锁推迟到 268/280 次调用，而模型先耗尽 100 轮；Repository Skill 仍描述旧的 44 轮与 80 次调用合同。
- guest runtime 现在同时按轮次和工具调用收敛。默认在第 80 轮且达到覆盖目标时锁定 `ls/find/grep/read`，第 90 轮无条件锁定；调用次数仍在 268/280 次形成软/硬锁。剩余预算只允许 `write_wiki` 与最终 manifest，并继续经过 Host Citation、Markdown、链接与 Dossier 校验。
- Code Agent Skill 已同步默认 `100 / 300` 合同和动态剩余预算提示；预算纯函数测试固定 `100 → 80/90`、`50 → 40/44`、纠错预算缩放，以及轮次/调用软硬锁行为。
