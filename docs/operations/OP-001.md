# OP-001：Askme 本地 Docker 基础环境

状态：`active`

关联 Plan：[PLAN-001](../plans/PLAN-001.md)
适用环境：本机 `askme-local` Docker Compose project

## 前置条件与边界

- Docker Engine 29.4.0、Docker Compose 5.1.1。
- 宿主端口仅绑定 loopback：Web `127.0.0.1:3000`，PostgreSQL `127.0.0.1:55432`，Mailpit UI/API `127.0.0.1:8025`；SMTP 仅在 Compose 网络使用 `mailpit:1025`。
- `scripts/docker-up.sh` 优先使用当前进程环境；存在 `~/.env` 时作为 Compose env file 补充。只有 Compose 声明的变量会进入容器。
- Compose 将 database、runtime/AI 与 bootstrap 凭证分为最小环境集合；账号明文密码只进入一次性 migrate/bootstrap 容器，DeepSeek key 只进入 Web/worker。
- 本操作只管理 `askme-local` 的 db、migrate、mailpit、web、worker、`askme_local_pgdata` 和 `askme_local_uploads`；不得操作其他项目容器。Mailpit 是本地验收依赖，不使用业务数据 volume。

## 启动与验证

```bash
scripts/docker-up.sh -d
docker compose ps
curl -fsS http://127.0.0.1:3000/api/health/ready
DATABASE_URL=postgresql://askme:askme-local-only@127.0.0.1:55432/askme npm run smoke:auth
```

本地 bootstrap 账号来自 `ASKME_CANDIDATE_*` 和 `ASKME_ADMIN_*`；示例值见 `.env.example`。bootstrap 只在账号不存在时创建，不自动覆盖已有密码。

## 已处置失败

1. PostgreSQL 18 拒绝把 volume 挂载到 `/var/lib/postgresql/data`。日志要求 18+ 挂载 `/var/lib/postgresql`；只读检查确认本轮新建 volume 为空后，删除该空 volume 并按新路径重建，随后 migration 成功。
2. standalone Web 默认绑定容器 hostname，导致 Docker healthcheck unhealthy 且登录 redirect 指向内部 hostname。Compose 现仅为 Web 设置 `HOSTNAME=0.0.0.0`，HTTP redirect 从外部 Host/forwarded headers 构造，修复后 web healthy 且 smoke 验证 `127.0.0.1` origin。

## 停止、恢复与显式 reset

- `docker compose stop` / `docker compose start` 保留数据。
- 普通恢复先执行 `docker compose ps` 与 ready 检查，再按本文件启动入口恢复，不删除 volume。
- `scripts/docker-reset.sh --confirm askme-local` 会删除 Askme 本地容器和两个命名 volume，属于显式 from-zero 操作；未获得清空授权时禁止执行。
